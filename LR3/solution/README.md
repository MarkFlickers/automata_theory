# Лабораторная работа № 3

Каркас программы минимизации не полностью определённого автомата Мили алгоритмом
Пола — Ангера. Уже реализованы чтение таблиц f и g, проверка их согласованности
и вывод автомата на экран. Четыре фазы алгоритма оставлены в `src/main.cpp`
в местах, помеченных `TODO`. Классы фаз появятся после обсуждения теории.

## Что готово

| Файл | Назначение |
| --- | --- |
| `src/main.cpp` | Чтение, вывод исходного автомата, места для фаз 1–4 |
| `include/Table.hpp`, `src/Table.cpp` | Таблица автомата: размеры и доступ к ячейкам |
| `TableItem`, `ItemState`, `ItemOutput` в `include/` и `src/` | Интерфейс ячейки и два вида значений (из ЛР2) |
| `include/FileIO.hpp`, `src/FileIO.cpp` | Чтение `f_table.txt`, `g_table.txt`; `FormatValue` |
| `include/Printer.hpp`, `src/Printer.cpp` | `ValidateAutomaton`, `PrintAutomaton` — проверка и вывод f и g рядом |
| `CMakeLists.txt` | Сборка и копирование входных файлов в `build` |

## Что предстоит реализовать

Состав классов задан методичкой, их устройство — на усмотрение студента.

| Фаза | Класс | Вход конструктора | Результат |
| --- | --- | --- | --- |
| — | `CompTable` | — | абстрактная таблица совместимости |
| — | `SCouple` | номера двух состояний | пара состояний |
| 1 | `PreCompTable : CompTable` | таблицы f и g | таблица предварительной совместимости, ячейки — `std::vector<SCouple>` |
| 2 | `FCompTable : CompTable` | `PreCompTable` | таблица полной совместимости |
| 3 | `SMaxComp` | `FCompTable` | классы максимальной совместимости `std::vector<std::vector<int>>`, метод `void Sort()` |
| 4 | — | отсортированный `SMaxComp` | таблицы f и g минимизированного автомата |

Новые `.cpp` добавляй в список `add_library(lab3_core ...)` в `CMakeLists.txt`.
Минимизированный автомат удобно хранить в тех же `Table` и выводить через
`PrintAutomaton(std::cout, f, g, "A")` — столбцы будут подписаны A1, A2, …

## Соглашения

- Номера входов и состояний в файлах начинаются с **1**, индексы
  `Table::Value(input, state)` — с **0**. `transitions.Value(0, 0)` — переход
  из s1 при x1; его значение равно 2.
- `kUndefinedValue == 0` означает `-`: переход или выход не задан.
- Строки таблиц — входы x1…x4, столбцы — состояния s1…s5.
- `Table` владеет ячейками через `unique_ptr` и не копируется: передавай её
  по константной ссылке или перемещай. Новую таблицу собирают из
  `std::vector<Table::Row>`, ячейки — `std::make_unique<ItemState>(n)` и
  `std::make_unique<ItemOutput>(n)`.

## Сборка

Команды выполняются из `LR3/solution`; нужны CMake, Ninja и компилятор C++20.

```powershell
cmake -S . -B build -G Ninja
cmake --build build
```

Каркас проверен с Ninja и GCC 15.2 (xPack). Методичка указывает Microsoft
Visual Studio: если сдаёшь через неё, отдельно проверь сборку там.

## Запуск

```powershell
Push-Location build
try { .\lab3.exe } finally { Pop-Location }
```

Программа ищет `f_table.txt` и `g_table.txt` в текущей рабочей папке, поэтому
запускается из `build`. После изменения входных файлов повтори конфигурацию
CMake, чтобы обновить их копии в `build`.

Сейчас программа печатает исходный автомат, заголовки фаз и останавливается
на `TODO [1]` — это ожидаемое поведение каркаса.
