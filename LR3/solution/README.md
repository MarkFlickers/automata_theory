# Лабораторная работа № 3

Программа минимизации не полностью определённого автомата Мили алгоритмом
Пола — Ангера. Выводит на экран исходный автомат, таблицы предварительной и полной
совместимости, классы максимальной совместимости и минимизированный автомат.

```text

    → SMaxComp(full)              классы максимальной совместимости
    → SMaxComp::Sort()            A1, A2, ... в порядке методички
    → MinAutomaton(classes, f, g) → вывод f и g по A1, A2, ...
```

## Устройство CompTable

Таблица хранит по ячейке `CompCell` на каждую пару (si, sj), i < j:

| `compatible` | `conditions` | Смысл | Печать |
| --- | --- | --- | --- |
| `false` | любые | несовместимы | `x` |
| `true` | пусто | безусловно совместимы | `v` |
| `true` | не пусто | совместимы при совместимости этих пар | `(2,3)(2,5)` |

- Читать может кто угодно: `IsCompatible(pair)`, `Conditions(pair)`, `StateCount()`.
- Менять ячейки — только наследники через `Cell(pair)` (protected).
- Ячейки при создании совместимы и без условий.
- `FCompTable(pre) : CompTable(pre)` копирует все ячейки предварительной таблицы;
  конструктору остаётся только вычёркивать.
- Отдельного флага «безусловно» нет: это `compatible && conditions.empty()`,
  поэтому противоречивой ячейки быть не может.

## Соглашения

- Номера входов и состояний в файлах и в `SCouple` начинаются с **1**, индексы
  `Table::Value(input, state)` — с **0**. `transitions.Value(0, 0)` — переход
  из s1 при x1; его значение равно 2.
- `kUndefinedValue == 0` означает `-`: переход или выход не задан.
- Строки таблиц — входы x1…x4, столбцы — состояния s1…s5.
- `Table` не копируется: передавай её по константной ссылке. Новую таблицу собирают
  из `std::vector<Table::Row>`, ячейки — `std::make_unique<ItemState>(n)` и
  `std::make_unique<ItemOutput>(n)`.
- Пара переходов не становится условием, если в ней есть `-`, если оба перехода
  ведут в одно состояние или если это та же пара.
- Классы максимальной совместимости ищутся табличным методом (столбцы справа налево);
  каждый класс хранится отсортированным по возрастанию.
- Порядок `Sort()`: 1) классы с состоянием, не встречающимся в других классах, —
  вперёд; 2) по убыванию размера; 3) лексикографически по возрастанию.
  Третий ключ методичка явно не называет, он следует из её примера.
- Выбор приёмника в фазе 4 (**принятое прочтение** правила методички): сначала
  текущий класс, затем все классы в порядке сортировки A1, A2, …
- Минимизированный автомат строится по **всем** классам максимальной совместимости,
  поэтому приёмник всегда существует. Результат не обязательно минимален:
  для варианта существует замкнутое покрытие {1,2}, {2,3}, {4,5} из трёх состояний.

## Ориентиры для варианта

Фаза 1:

```text
    s1          s2     s3     s4
s2  (2,3)
s3  (2,3)(2,5)  (4,5)
s4  (2,3)       (1,5)  (1,4)
s5  (1,3)       x      v      (1,2)
```

Фаза 2: вычёркивание (2,5) → (1,3) → (1,5) → (2,4); совместимы
(1,2), (1,4), (2,3), (3,4), (3,5), (4,5).

Фаза 3: {3,4,5}, {2,3}, {1,4}, {1,2}; после `Sort()` —
A1 = {3,4,5}, A2 = {1,2}, A3 = {1,4}, A4 = {2,3}.

Фаза 4:

```text
    f                g
    A1 A2 A3 A4      A1 A2 A3 A4
x1   1  4  2  4       1  1  1  1
x2   3  1  3  1       2  2  2  2
x3   2  4  4  4       2  1  -  1
x4   1  2  2  1       1  1  1  1
```

## Сборка

Команды выполняются из `LR3/solution`; нужны CMake, Ninja и компилятор C++20.

```powershell
cmake -S . -B build -G Ninja
cmake --build build
```

Каркас проверен с Ninja и GCC 15.2 (xPack). Методичка указывает Microsoft
Visual Studio: если сдаёшь через неё, отдельно проверь сборку там.

## Запуск

```powershell
Push-Location build
try { .\lab3.exe } finally { Pop-Location }
```

Программа ищет `f_table.txt` и `g_table.txt` в текущей рабочей папке, поэтому
запускается из `build`. После изменения входных файлов повтори конфигурацию
CMake, чтобы обновить их копии в `build`.
